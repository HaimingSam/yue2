## 每首歌生成什么？

```text
clips/<编号>/
  reference.wav          12 秒参考人声，48 kHz、单声道
  reference_16k.wav      同一段参考人声的 16 kHz 版本
  target_01.wav          15 秒原曲混音，48 kHz、双声道
  target_vocal_01.wav    与目标 01 同时间段的人声，48 kHz、单声道
  target_02.wav          第二段目标混音（足够有效片段时才有）
  target_vocal_02.wav    与目标 02 同时间段的人声
  metadata.json         源文件、裁剪时间、活动比例、格式、哈希、警告
```

所有输出都是 float32 WAV，不再进行有损压缩，也不做音量归一化、限幅或人为改变速度。48 kHz 重采样不会恢复原曲压缩时已经损失的信息。16 kHz 参考只是方便后续接编码器，实际使用哪种采样率以选定编码器为准，不能混用不同预处理。

目标干声留作后续歌词/旋律处理和质量检查；当前完整歌曲 NAR 的声学监督应使用目标混音，而不是把目标干声直接当完整音乐目标。

## 怎么选择片段？

1. 分离人声转为 8 kHz 单声道，仅供低成本活动分析，不作为输出音频。
2. 按 100 毫秒计算 RMS 能量；门限为 `max(-50 dBFS, 第90百分位能量-25 dB)`。
3. 候选段每秒滑动，至少 70% 时间高于活动门限；首尾预留 2 秒。
4. 每首选一个 12 秒参考、最多两个 15 秒目标，尽量选活动较充分的片段。
5. 参考与目标、不同目标之间均不重叠，并至少间隔 3 秒。
6. 不足以组成参考/目标的短歌、低活动歌曲或处理失败的歌曲，写入跳过清单，不强行复制或补零。

这只是**基于能量的粗筛**，不是歌声识别，也不是人工试听。它不能可靠判断合唱、多歌手、歌词重复、伴奏残留、分离伪影或音色质量。两个不重叠的副歌仍可能内容相似，因此不能据此保证没有歌曲信息泄漏。

原曲与分离人声在本次审计中最大时长差约 51 毫秒。这不代表测量过两条波形的时间偏移。目标干声与混音使用相同秒数裁剪，但没有进行互相关对齐或时间拉伸。

## 数据划分与文件说明

固定随机种子 `20261009`，按完整编号划分约 90% 训练、10% 验证。同一编号全部片段放在同一侧。若不同编号的原曲文件 SHA256 完全相同，也会放在同一侧；本次审计未发现这种精确重复。不同编码版本的重复歌曲不能靠文件哈希识别。

```text
1000-1-prepared/
  audit_config.json          原始目录记录
  inventory.json             全部源文件格式、时长和文件信息
  audit_summary.json         审计统计
  prepare_config.json        切片参数
  split_assignments.json     固定划分
  clips/                     处理后的 WAV
  audio_train.jsonl          训练侧音频素材清单
  audio_validation.jsonl     验证侧音频素材清单
  prepare_errors.json        跳过/失败编号及原因
  prepare_summary.json       成功数量、时长、磁盘占用、警告统计
  verification.json          完成后的完整性核验结果
```

清单中的音频路径均相对于本数据目录。每个目标片段是一条样本，同一首歌的两个样本复用同一参考人声。

## 重要：还不能直接传给 train

清单特意命名为 **`audio_train.jsonl`**，每条都标记：

```json
{"stage":"audio_only","training_ready":false}
```

它不是 `yue2.voice_training train` 所需的完整训练清单。当前仍缺：

1. 选定预训练音色编码器，再提取参考 `reference.npy`；
2. 选定对应 VAE，将目标混音编码成 `target.npy`；
3. 与目标演唱对应的 `prefix.npy` 和 `semantic.npy`。

**本次没有伪造 semantic tokens，没有用 AR 随机重唱结果冒充原唱标签，也没有把数据标为已对齐 `paired`。** 原曲裁剪和格式转换无法解决缺少 tokenizer 的问题。重新生成的 c 配原曲属于未验证实验，即使时长相同也不能认为对齐。

参考与目标不需要等长或逐样本同步；需要内容/时序对应的是 **目标音频和它的 semantic tokens**。后续训练说明见 `docs/nar-voice-training.md`。

## 复现与续跑

以下命令从仓库根目录执行。

审计必须使用新输出目录，拒绝覆盖已有数据集：

```sh
.venv/bin/python tools/prepare_voice_audio.py audit \
  --vocals /data/cmq/datas/1000-1-urv_separated \
  --sources /data2/cmq/datas/1000-1-audio/raw \
  --output voice-data/1000-1-prepared --workers 6
```

切片可用相同参数续跑，已经完成的 WAV 验证哈希后复用，不重新编码。若参数或原文件大小/修改时间变化，会拒绝复用，避免悄悄混入不同版本数据：

```sh
.venv/bin/python tools/prepare_voice_audio.py prepare \
  --output voice-data/1000-1-prepared --workers 6
```

`--limit 4` 仅用于首次小样本试跑；之后去掉它处理全量。不要在已有全量结果上加 `--limit` 重建清单，否则该次清单只包含所选子集。未在该次清单中的原输出文件不会删除。

核验清单、样本划分、裁剪区间、WAV 格式及全部音频 SHA256：

```sh
.venv/bin/python tools/prepare_voice_audio.py verify \
  --output voice-data/1000-1-prepared
```

核验通过仅代表文件完整性和划分正确，不代表实际歌手身份、音质或 semantic 对齐通过。
